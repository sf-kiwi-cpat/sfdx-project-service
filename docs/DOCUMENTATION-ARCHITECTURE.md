# Documentation Architecture

How documentation is structured and maintained in this repo. This file is
the source of truth for the `/docs-standards` audit skill.

## Philosophy

Progressive disclosure. Top-level docs are short orientation guides that link
to detailed references in `docs/`. No information is repeated across files.
Each fact has one canonical home.

Each file has one audience and one purpose. If a file tries to serve two
audiences, split it.

CLAUDE.md is loaded into every agent session. Keep it small and high-signal.
Only include what agents need in every session. Everything else goes in
`docs/` and gets loaded on demand.

overwrite it. **sync-docs** means auto-generated by the `/sync-docs` skill.

## Where does new content go?

| Content type | Destination |
|-------------|-------------|
| Workflow, process, SDLC | `docs/workflow-guide.md` |
| Dev setup, tooling, testing | `docs/development.md` |
| API behavior, endpoints | `docs/api.md` |
| System design, data flow | `docs/architecture.md` |
| Module interfaces, exports | `docs/modules.md` |
| Agent-critical (every session) | `CLAUDE.md` (keep it lean) |
| Human onboarding | `CONTRIBUTING.md` (link to details, don't duplicate) |
| Documentation rules | `docs/DOCUMENTATION-ARCHITECTURE.md` |

## CLAUDE.md scope

Belongs in CLAUDE.md (agents need this every session):
- npm scripts and dev commands
- Git hook behavior
- CDD skill list and label lifecycle (concise)
- Directory layout (`src/`, `spec/`, `tests/`)
- Guardrail rules (`spec/` is human-guarded, `tests/` is agent-mutable)
- Worktree gotchas
- Git conventions (branches, commits, PRs)

Does not belong in CLAUDE.md (load from docs/ on demand):
- Full workflow walkthroughs
- Monitor loop setup instructions
- Troubleshooting guides
- Docker instructions

The label lifecycle stays in CLAUDE.md because agents need to know the
state machine to set labels correctly, but the detailed walkthrough and
loop setup live in `docs/workflow-guide.md`.

Target: under 125 lines.

## CONTRIBUTING.md scope

Quick-start orientation, readable in under 2 minutes. Answers "I'm new,
where do I start?" Maximum ~50 lines. Lists prerequisites, a 4-line quick
start, a brief workflow summary, and links to `docs/` for everything else.
Never duplicates content from `docs/development.md` or
`docs/workflow-guide.md`.

## Anti-patterns

**Duplication.** Same information in multiple files. Pick one canonical home
and link from elsewhere.

**CLAUDE.md bloat.** Putting detailed workflow or process info in CLAUDE.md.
Move it to `docs/workflow-guide.md`, leave a link.

**Orphan files.** Creating markdown files without adding them to the
inventory table above.

**CONTRIBUTING.md depth.** Expanding CONTRIBUTING.md into a full guide.
Link to the relevant `docs/` file instead.

**Manual edits to sync-docs files.** Files marked as sync-docs maintained
will be overwritten on the next run. Change the source code or templates
instead.
